BundlePortal API v2 Webhooks
===========================

Callback endpoint
-----------------

POST https://superdatagh.com/bundleportal/orders

The route accepts BundlePortal final order events:

- order.completed -> completed
- order.failed -> failed
- order.cancelled -> cancelled
- order.refunded -> refunded

BundlePortal status updates are delivered by webhook; the v2 status polling
command does not poll the API.

Registering or rotating the webhook
-----------------------------------

Set APP_URL to the public HTTPS site and BUNDLEPORTAL_API_KEY in .env, then run:

    php artisan bundleportal:register-webhook

Pass --url=https://your-domain/bundleportal/orders to register another public
HTTPS URL. The command calls BundlePortal's set_webhook action and saves the
one-time response secret to BUNDLEPORTAL_WEBHOOK_SECRET in .env without
printing it. Running the command again may rotate the secret; use it only when
you intend to register or rotate the webhook.

Signature verification
----------------------

The handler reads BUNDLEPORTAL_WEBHOOK_SECRET (falling back to the legacy
WEBHOOK_SECRET) and checks X-BundlePortal-Signature against the raw request
body using the sha256=<hex HMAC-SHA256> format currently implemented by the
app. Invalid or missing signatures are rejected before the order is changed.

After adding or changing the secret, clear Laravel's config cache with:

    php artisan config:clear
